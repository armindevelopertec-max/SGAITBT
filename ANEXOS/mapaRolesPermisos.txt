2) DECISIONES ACORDADAS
--------------------------------------------------------------------------------
a) Implementar TODO el modelo de una vez (no por fases).
b) Multi-rol: un USUARIO puede tener varios ROLES a la vez
   (tabla user_roles, many-to-many).
c) HERENCIA de permisos segun el arbol:
   - EMPLEADO -> DIRECTIVO -> RECTOR
   - EMPLEADO -> DOCENTE
   - EMPLEADO -> ADMINISTRATIVO -> SECRETARIA
   - EMPLEADO -> APOYO
   Los permisos efectivos = union de los propios + todos los ancestros.
d) Granularidad de PERMISOS por modulo y accion: view / create / edit / delete / manage / print.
e) Mapeo de acceso:
   - ADMIN            = todo (superusuario)
   - RECTOR/DIRECTIVO = lectura total + reportes
   - DOCENTE          = notas y asistencia (como TEACHER actual)
   - SECRETARIA       = matriculas, depositos, periodos (lo mismo que hoy)
   - ADMINISTRATIVO   = lectura + matriculas basicas (sin asignacion de materias ni periodos)
   - APOYO            = lectura minima
   - ESTUDIANTE       = su dashboard estudiantil (como hoy)
